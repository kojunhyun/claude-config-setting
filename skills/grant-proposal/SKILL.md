# Grant Proposal — 정부과제 제안서 + PPT 시각자료

AI 개발 팀장 관점에서 정부과제 제안서를 작성한다. 핵심 원칙:
- **현실적이고 수행 가능한** 계획 (장밋빛 미래 X, 단계적 마일스톤 O)
- **비전공자도 이해**할 수 있게 (쉬운 비유, 명확한 예시)
- **전문성 동시 확보** (구체 기술 명세, 정량 목표)
- 시각자료는 **PPT에 캡처해 넣기 좋게** 흰 배경, 16:9 비율 (1920×1080) 기준

## 입력

사용자가 `/grant {공고 파일 경로}` 또는 공고 텍스트를 붙여넣음. 가능한 입력:
- PDF 공고
- HWP/DOCX (변환 가능하면)
- 공고 URL
- 공고 내용 텍스트 직접

## 산출물

작업 디렉토리: `/mnt/d/00_Project/grant-{공고요약}/`

```
outputs/grant-{slug}/
├── 01-analysis.md           ← 공고 분석
├── 02-tech-research.md      ← 관련 기술 동향
├── 03-proposal.md           ← 본문 (한글, .md)
├── 03-proposal.docx         ← 본문 워드 변환 (선택)
├── pipeline/
│   ├── style1-minimal.html
│   ├── style2-infographic.html
│   ├── style3-flowchart.html
│   ├── style4-layered.html
│   ├── style5-timeline.html
│   └── INDEX.html           ← 5종 한눈에 비교
└── README.md
```

## Stage 1: 공고 분석

산출물: `01-analysis.md`

추출할 항목 (없으면 "미명시" 표시):
- **사업명 / 공고번호 / 주관기관**
- **사업 분야 / 키워드**
- **총 예산 규모 + 과제당 한도**
- **수행 기간** (연차별)
- **참여 자격** (기업/대학/연구소 등)
- **평가 항목 + 배점** (가장 중요)
- **필수 제출 양식 / 분량**
- **마감일**
- **심사위원 성향 추정** (해당 기관의 과거 선정 트렌드 — 추정 명시)

평가 항목별로 우리가 어떻게 점수를 따낼지 1줄 메모를 함께 작성.

## Stage 2: 기술 동향 조사 (tech-research 스킬 재사용)

`02-tech-research.md`에 다음 정리:
- 해당 분야 국내외 SOTA
- 우리가 차별화할 수 있는 지점 2-3개
- 경쟁/유사 과제 (있다면)
- 인용 가능한 출처 (논문, 보고서)

웹 서치 적극 활용. 단 출처 명시 (저자/연도/제목).

## Stage 3: 제안 본문 작성

산출물: `03-proposal.md`

표준 구조 (공고에 명시된 양식 있으면 그것 우선):

```markdown
# {과제명}

## 1. 과제 개요
- 한 문장 요약 (비전공자가 읽고 이해 가능)
- 해결하려는 문제 (구체 사례)
- 제안하는 해결 방식 (1단락)

## 2. 추진 배경 및 필요성
- 사회/산업적 필요성 (정량 지표 + 출처)
- 기술적 필요성 (현재 한계 + 우리가 메울 부분)
- 정부 정책 부합성 (해당 사업 목적과의 연결)

## 3. 연구 목표 및 내용
### 최종 목표
- 정량 목표 (수치 + 측정 방법)

### 연차별 목표
- 1차년도: ...
- 2차년도: ...
- (3차년도: ...)

### 세부 연구 내용
1. {모듈명}
   - 무엇을, 왜, 어떻게 (3줄)
2. ...

## 4. 기술 차별성 및 경쟁력
- 국내외 기술 수준 (Stage 2 인용)
- 우리의 차별 포인트 3가지
  - 차별점 1 + 근거
  - 차별점 2 + 근거
  - 차별점 3 + 근거

## 5. 추진 체계
- 참여 기관 + 역할 분담 (텍스트, 다이어그램은 별도 HTML)
- 컨소시엄 시너지 (필요 시)

## 6. 수행 일정 (간트차트는 별도 HTML)
- WBS 표

## 7. 기대 효과
- 기술적 효과 (정량)
- 경제적 효과 (시장 규모 × 점유율 가정)
- 사회적 효과

## 8. 예산 (해당 사업 가이드 따라)
- 인건비 / 직접비 / 간접비 비율 가이드
- 단, 정확한 단가는 사용자가 입력해야 함 → 자동 작성 시 placeholder

## 9. 위험 요소 및 완화 방안
- 기술적 위험 + 대응
- 일정 위험 + 대응
```

## 글쓰기 톤

- 한 문장은 한 가지 주장
- 평균 문장 길이 50자 내외
- 정량 표현 우선 ("크게 향상" X, "30% 향상" O)
- 추정 수치는 "추정" 표시
- 인용은 (저자, 연도) 형식
- AI 기술 전문용어 처음 등장 시 1줄 설명 ("Transformer(어텐션 기반 신경망 구조)")

## Stage 4: 시각자료 5종 생성

각 HTML은 `~/.claude/templates/grant/style*.html` 템플릿을 베이스로,
프로젝트 내용에 맞게 텍스트/노드/단계만 치환한다.

**5종 시각 언어 차별화**:

| 스타일 | 시각 언어 | 적합한 상황 |
|--------|-----------|-------------|
| style1-minimal | 가는 회색 라인, 산세리프, 여백 강조 | 학술적/정제된 느낌 필요 시 |
| style2-infographic | 컬러 블록 + 아이콘 + 숫자 | 임팩트 강조, 발표 슬라이드 |
| style3-flowchart | 노드+화살표, 단계별 흐름 | 프로세스 명확화 |
| style4-layered | 데이터/모델/서비스/UI 레이어 가로띠 | 시스템 아키텍처 |
| style5-timeline | 1년차/2년차/... 마일스톤 타임라인 | 일정 + 단계 강조 |

**공통 규약** (모든 스타일):
- viewBox 1920×1080 (16:9, FullHD)
- 배경 흰색 `#ffffff`
- 폰트: 'Pretendard', 'Noto Sans KR', system-ui (한글 가독성)
- 인쇄/캡처 시 손실 없게 SVG로 모든 요소 그리기 (텍스트도 SVG <text>)
- 외부 폰트 의존 최소화 (CDN은 본문에 포함하지만 fallback 보장)

각 HTML 파일은 사용자가 브라우저로 열고 → 풀스크린 캡처(예: 1920×1080 스크린샷) → PPT에 붙여넣기 가능해야 한다.

`INDEX.html`은 5종을 iframe 또는 thumb로 한 페이지에 보여주어 비교 가능하게.

## Stage 5: 최종 정리

`README.md`에 다음 기록:
- 어떤 공고를 분석했는지 (요약)
- 본문 .md를 .docx로 변환 권장 (사용자가 직접: pandoc 또는 워드)
- 시각자료 5종 어떤 슬라이드에 어떻게 쓰면 좋은지 가이드

## 사용자와의 상호작용

- Stage 1 끝나면 분석 결과 보여주고 "방향성 맞나요?" 1회 확인
- Stage 3 끝나면 본문 초안 보여주고 수정 의견 받기
- Stage 4는 자동 진행 (5종 다 만든 후 INDEX.html 안내)

## 무엇은 하지 말 것

- **거짓 실적 만들지 말 것** — 사용자가 입력 안 한 실적/논문/특허 임의 생성 금지
- **예산 임의 결정 금지** — placeholder만 두고 사용자 확인 요청
- **표절 위험** — 다른 제안서 또는 논문 문장 그대로 복사 금지
