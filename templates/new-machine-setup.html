CLAUDE CONFIG · MULTI-MACHINE

새 PC Claude Config 셋업 가이드

git clone → bootstrap → paths.local.env 편집 → /setup-status. 자동화 가능한 건 다 자동, 외부 시스템 등록만 사람이. 실 작업 시간 약 5–10분 (외부 등록 별도).

1 Clone + bootstrap ~2분

레포 클론 후 bootstrap 한 번이면 심볼릭링크 / env / SSH 키 / 회사 폴더 / 플러그인 모두 자동.

# WSL / Linux / macOS
git clone https://github.com/kojunhyun/claude-config-setting.git ~/claude-config
cd ~/claude-config
./bootstrap.sh

# Windows 단독
git clone https://github.com/kojunhyun/claude-config-setting.git D:\00_Claude_Config
cd D:\00_Claude_Config
.\bootstrap.ps1

bootstrap 이 자동으로 처리하는 것

  • ✅ ~/.claude/{agents,commands,skills,templates} 심볼릭링크 → 레포
  • ✅ ~/.claude/CLAUDE.md 심볼릭/카피
  • ✅ ~/.bashrc 또는 $PROFILE 에 env vars + paths.env auto-source 블록
  • ✅ paths.local.env 자동 생성 (MACHINE_ID, NOTION_TOKEN placeholder)
  • ✅ SSH key 자동 생성 (id_ed25519, id_ed25519_aixera) — 없을 때만
  • ✅ 회사 폴더 자동 mkdir (OS별: WSL=/mnt/d/Aixera, Mac=~/Aixera, Linux=~/Aixera)
  • ✅ plugins.manifest 의 플러그인 자동 설치 (ECC 등)
  • ✅ git post-merge hook 활성
참고 — bootstrap.ps1 한계

Windows 네이티브 bootstrap.ps1 은 SSH key / 회사 폴더 자동 생성 미반영 (WSL/Mac/Linux 만). Win+WSL 환경이면 WSL 의 bootstrap.sh 가 처리하므로 영향 없음.

2 paths.local.env 편집 ~2분

머신별/secret 만 사람이 채움. 위치: $CLAUDE_CONFIG_DIR/paths.local.env (gitignored).

vi $CLAUDE_CONFIG_DIR/paths.local.env

채워야 할 항목

변수값 예시설명
CLAUDE_MACHINE_ID jhko-mac-mini 이 머신의 고유 이름. bootstrap 이 hostname-user 로 디폴트 세팅했으니 의미있게 변경
CLAUDE_WEEKLY_LEADER true 또는 빈값 일일/주간 통합 담당. 전체 머신 중 1대만 true. Mac mini 권장
CLAUDE_LOG_NOTION_PERSONAL_TOKEN "secret_xxx..." 개인 Notion integration secret (4단계에서 발급)
CLAUDE_LOG_NOTION_WORK_TOKEN "secret_yyy..." 회사 Notion integration secret (4단계에서 발급)

예시

# Mac mini (leader 머신)
CLAUDE_MACHINE_ID=jhko-mac-mini
CLAUDE_WEEKLY_LEADER=true
CLAUDE_LOG_NOTION_PERSONAL_TOKEN="secret_abc...123"
CLAUDE_LOG_NOTION_WORK_TOKEN="secret_def...456"

# Ubuntu (non-leader)
CLAUDE_MACHINE_ID=jhko-ubuntu-prod
CLAUDE_WEEKLY_LEADER=
CLAUDE_LOG_NOTION_PERSONAL_TOKEN="secret_abc...123"
CLAUDE_LOG_NOTION_WORK_TOKEN="secret_def...456"

셸 재시작 (또는 source ~/.bashrc) 해야 적용됨.

문법 주의
  • 공백 / 한글 / 특수문자 값은 반드시 따옴표
  • $VAR expansion 사용 금지 (PowerShell 호환 위해 literal 만)
  • 빈 값 = SKILL fallback 사용

4 외부 시스템 등록 (수동) ~5–10분

자동화 불가능한 외부 시스템 작업. 머신마다 한 번씩.

4-1 · GitHub 공개키 등록

cat ~/.ssh/id_ed25519.pub
# 출력된 한 줄 복사
  • →브라우저: https://github.com/settings/keys
  • →New SSH key 클릭 → Title (예: jhko-mac-mini) → Key 칸 paste → Add SSH key
  • →검증: ssh -T git@github.com → Hi kojunhyun! 같은 메시지

4-2 · GitLab (Aixera) 공개키 등록

cat ~/.ssh/id_ed25519_aixera.pub
  • →브라우저: https://gitlab.aixera.net 로그인 → Preferences → SSH Keys
  • →Add new key → Title (예: jhko-mac-mini) → Key 칸 paste
  • →Usage type: Authentication & signing, Expiration date 비움
  • →검증: ssh -T git@gitlab.aixera.net

4-3 · Notion Integration Token 발급 (워크스페이스마다 1회)

개인/회사 워크스페이스 각각 한 번씩. 모든 머신에서 같은 token 재사용.

  • →브라우저: https://www.notion.so/profile/integrations
  • →New integration → Name (예: Claude Logs (Personal)) → Associated workspace 선택 → Type: Internal
  • →Capabilities: Read / Update / Insert content 모두 ✓
  • →Save → 다음 화면에서 Internal Integration Secret 복사 (한 번만 표시!)
  • →Notion 부모 페이지(예: "Claude Logs") 에서 ... → Connections → Add → 방금 만든 integration
  • →token 을 paths.local.env 의 CLAUDE_LOG_NOTION_PERSONAL_TOKEN 또는 _WORK_TOKEN 에 paste
잘 잊는 단계

Notion 부모 페이지에 integration share 안 하면 401 / 404. 새 페이지에 쓰려면 그 페이지 (또는 부모) 에 integration 권한 부여 필수. 하위 페이지에는 권한 자동 상속됨.

5 검증 ~1분

실제 동작 확인.

# SSH 연결
ssh -T git@github.com
ssh -T git@gitlab.aixera.net

# Notion token (개인 / 회사 각각)
curl -sS https://api.notion.com/v1/users/me \
  -H "Authorization: Bearer $CLAUDE_LOG_NOTION_PERSONAL_TOKEN" \
  -H "Notion-Version: 2022-06-28"
# → 200 + bot 정보면 OK

# 첫 daily-log (raw 페이지 생성, 부모 페이지 자동 생성)
claude
> /daily-log

# 다시 setup-status — 모든 ✅ 면 끝
> /setup-status

회사 repo 첫 clone 테스트

cd /mnt/d/Aixera
git clone git@gitlab.aixera.net:GROUP/PROJECT.git
cd PROJECT
git config user.email
# → jhko@aixera.co.kr 가 나와야 정상 (자동 전환 확인)

★ 머신 역할별 차이

역할머신 예paths.local.envschedule 등록
LEADER Mac mini CLAUDE_WEEKLY_LEADER=true /daily-log (22:00) +
/daily-log-aggregate (23:00) +
/weekly-log (목 12:30)
non-leader WSL desktop, Ubuntu CLAUDE_WEEKLY_LEADER= (빈값) /daily-log 만 (22:00). aggregate / weekly 호출돼도 자동 종료.

스케줄 등록 명령

# 모든 머신에서 (raw daily)
/schedule create daily-raw "0 22 * * *" run /daily-log

# Leader (Mac mini) 만 추가
/schedule create daily-aggregate "0 23 * * *"  run /daily-log-aggregate
/schedule create weekly-summary  "30 12 * * 4" run /weekly-log

cron 으로 등록할 때 (시스템 cron)

# 모든 머신
0  22 * * *  claude -p "/daily-log"             >> ~/.claude/logs/daily.log     2>&1

# Leader (Mac) 만 추가
0  23 * * *  claude -p "/daily-log-aggregate"   >> ~/.claude/logs/aggregate.log 2>&1
30 12 * * 4  claude -p "/weekly-log"            >> ~/.claude/logs/weekly.log    2>&1

? 트러블슈팅

증상원인해결
bootstrap 후 슬래시 명령 안 보임 Claude Code 재시작 안 함 exit 후 claude 다시 실행
paths.local.env 에 값 넣었는데 적용 안 됨 셸 rc 미 reload source ~/.bashrc 또는 셸 재시작
회사 폴더 안에서도 개인 이메일 ~/.gitconfig 의 includeIf 패턴 mismatch git config --list --show-origin | grep email 로 확인. ~/.gitconfig 의 gitdir: 패턴을 실제 폴더로 수정 (끝 슬래시 필수)
Notion 401 token 오류 또는 만료 curl ... /users/me 로 검증. 실패면 Notion 에서 rotate / 재발급
Notion 404 부모 페이지에 integration share 안 됨 해당 Notion 페이지 → ... → Connections → Add integration
ssh -T git@gitlab.aixera.net 무응답 회사 VPN 미연결 또는 사내망 외부 VPN / cloudflared / 회사 네트워크 확인
cron 으로 안 돌아감 cron 환경에 env vars 없음 cron 진입점에서 source ~/.bashrc 후 claude -p ...
같은 머신에서 daily-log 가 다른 머신 분도 잡아감 잘못된 MACHINE_ID 또는 vault 미동기화 echo $CLAUDE_MACHINE_ID 확인. Obsidian vault 가 모든 머신에서 같은 경로인지
